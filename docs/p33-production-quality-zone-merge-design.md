# P33 설계 문서 — 생산동·품질동 통합 (가공/조립/품질/물류 구역화)

> 상태: **설계 초안 — P32 D8~D10 안정화 이후 착수 권장.**
>
> 요청 원문: "생산동 품질동 가공동 조립물류동은 합치고 거기 안에서 분류 하는것은
> 어떻게 생각에? 그럼 조금 더 로봇이 세밀하게 움직이는 것 처럼 보일 수 있을것 같아."

---

## 0. 배경 — 생각보다 리스크가 낮은 이유

`NodeMap.java` 주석 기준으로 지금도 이미 이렇게 배치돼 있다:

```
창고동(1~54) — 게이트 — 생산동(58~90) — 게이트 — 품질동(94~102)
                        ├ A1~A4(가공)
                        └ B1~B4(조립)
```

즉 "가공동"과 "조립물류동"은 이미 별도 건물이 아니라 **생산동 내부의 구역**으로
존재한다(A행=가공, B행=조립). 이번 제안에서 실제로 새로운 부분은 **품질동(현재
`QC-IN`/`QC-OUT` 노드 2개뿐인 사실상 빈 건물)을 생산동 내부 구역으로 흡수하는
것** 하나뿐이다. 그래서 "건물 네 개를 합친다"보다는 "이미 3/4 되어 있는 통합을
마저 끝낸다"에 가깝다.

**기대 효과(요청자 가설 검증)**: 지금은 로봇이 건물 사이를 게이트 통과라는 단순
이벤트로 넘나든다. 가공→조립→품질→물류를 한 건물 안의 구역 이동으로 바꾸면
웨이포인트가 늘어나서 "세밀하게 움직이는" 인상이 실제로 강해질 것으로 보인다 —
P32에서 창고동 밀도를 올렸을 때와 같은 원리다.

---

## 1. 핵심 원칙 재확인

| 원칙 | 이 설계가 지키는 방법 |
|---|---|
| 기존 A/B 구역 좌표 무변경 | A1~A4, B1~B4는 손대지 않는다 — 품질 구역만 새로 편입 |
| AMR/AGV 경계 유지(P22) | 통합 건물 내부는 계속 AMR 담당(현재도 AMR이 생산동·품질동을 돈다) — 역할 자체는 안 바뀜 |
| 물류 흐름 불변 | "창고동(자재) → 생산동(가공) → 품질동(전수 검사)"라는 매크로 흐름은 그대로 — 물리적으로만 한 건물이 된다 |
| 논리와 물리를 분리 | QMS가 참조하는 "품질동"이라는 개념은 좌표가 아니라 **구역 코드**로 유지(2절 D4) |

---

## 2. 확정 결정 (D1 ~ D6)

### D1. 병합 범위 — 생산동 + 품질동을 하나의 물리적 건물로

내부 구역 4개로 재편: **가공(A)**·**조립(B)**·**품질(Q)**·**물류(L, 신규)**.
물류 구역은 현재 명시적으로 존재하지 않는 개념이라 이번에 신설한다 — 조립 완료품이
품질 구역으로 넘어가기 전 잠깐 머무는 WIP 스테이징 존 정도로 정의한다.

### D2. 좌표 재구성 — 품질 구역만 이동, A/B는 무변경

`QC-IN`(97, 21)·`QC-OUT`(97, 6)을 생산동 우측 끝(현재 90 부근) 안쪽으로 당겨온다.
정확한 좌표는 A/B 구역과의 클리어런스(≥1.75)를 확인하며 구현 시 확정 — 이 문서는
방향만 정한다. 기존 PROD↔QC 사이 게이트(90~94 구간)는 **건물 간 게이트에서 구역
간 경계**로 격하된다.

### D3. 물류(L) 구역 — WIP 스테이징으로 신설

가공(A)·조립(B) 출력과 품질(Q) 입력 사이에 위치. 지금 QMS의 `QUALITY_HOLD`
이벤트가 걸렸을 때 제품이 대기하는 자리로도 쓸 수 있어, 기존 MRB 대기 개념과
자연스럽게 연결된다(현재 대시보드에도 "MRB 대기" 큐가 이미 시각적으로 존재).

### D4. 논리적 구역 코드 유지 — QMS `building_code` 하위호환

물리적으로는 한 건물이지만, QMS가 이벤트·API에서 참조하는 "품질동" 개념은
좌표가 아니라 **구역 코드**(`zone: "QUALITY"`)로 유지한다. A/B 구역이 이미 이
방식(좌표는 생산동 소속, 논리적으로는 가공/조립 구분)으로 동작하고 있으니 같은
패턴을 재사용 — QMS 쪽 코드 변경 없이 좌표만 옮기는 것이 목표.

### D5. 신관(BLDG-A/B) 좌표 기준점 재설정

P30 주석에 "신관은 품질동과 나란히 +13"이라고 기준점이 명시돼 있다. 품질동이
생산동에 흡수되면 이 기준점을 **통합 건물 우측 끝** 기준으로 다시 잡아야 한다.
신관 자체의 좌표·역할은 안 바꾼다 — 기준점만 갱신.

### D6. 게이트 → 구역 경계 전환 시 로직 영향 확인

기존 PROD↔QC 게이트 통과가 어떤 이벤트(예: 로그·메트릭 트리거)에 걸려있다면,
구역 경계로 바뀐 뒤에도 같은 이벤트가 발생하는지 확인 필요 — 이번 설계에서
가장 확인이 부족한 지점이라 실행 단계 초반에 검증한다.

## 4. 리스크 & 롤백

- **D6이 가장 불확실하다.** 게이트 통과 이벤트에 의존하는 로직이 있다면 구역 경계
  전환 후 조용히 안 걸릴 수 있다 — 실행 전 관련 코드를 먼저 검색해서 확인.
- **P32와 시기가 겹치면 안 된다.** 창고동(P32)과 생산동(P33)이 동시에 좌표가
  흔들리면 둘 중 뭐가 원인인지 구분이 안 된다. P32가 먼저 안정화된 뒤 착수.
- **롤백**: D2/D3는 새 마이그레이션 파일 하나로 되돌릴 수 있는 수준(P28/P30급,
  P32의 D6 재발번급은 아님) — QC 노드 좌표만 옮기는 것이라 전면 재발번은 아니다.

---

## 5. 이번엔 안 하는 것

- **신관을 통합 건물에 편입하는 것** — 이번 요청 범위 밖. 기준점만 갱신하고
  신관 자체는 계속 별도 건물로 둔다.
- **게이트 개념 자체를 없애는 것** — 창고동↔생산동 게이트는 그대로 유지(AMR/AGV
  경계라는 실제 의미가 있음, P22). 이번엔 생산동↔품질동 사이의, 의미가 약한
  게이트만 구역 경계로 바꾼다.
